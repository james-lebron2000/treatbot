# 临床试验匹配平台（Demo）— 产品总览

> 目标：让「上传病历 → 结构化解析 → 匹配临床试验 → 输出可行动建议」形成可交付的最小闭环，并为后续合规/规模化做好接口与运维准备。

## 1. 一句话定义

一个面向患者与医疗服务人员的临床试验匹配平台：通过 OCR + 医疗文本解析 + 规则/LLM 匹配，输出候选临床试验与匹配理由，帮助更快定位可入组机会。

## 2. 目标用户与角色

- **患者（Patient）**：上传/粘贴病历材料，查看结构化信息与匹配结果，保存候选试验。
- **运营/医生助理（Coordinator）**：为患者建档、补全信息、快速批量匹配、导出沟通要点。
- **管理员/开发运维（Admin/DevOps）**：部署系统、配置 OCR/LLM、监控健康状态与成本。

> 本仓库当前以 Demo 为主：认证、患者建档、上传解析、匹配与历史回看均提供基础能力。

## 3. 核心场景（MVP）

### 场景 A：患者自助匹配（主链路）
1. 注册/登录
2. 创建患者档案（姓名/编号/联系方式等）
3. 上传病历（PDF/图片/文本）并 OCR
4. 解析为结构化病情要点（诊断、分期、基因、治疗史等）
5. 启动匹配（支持批处理 + SSE 流式进度）
6. 查看结果、筛选、保存候选试验

### 场景 B：运营协助匹配（更贴近真实落地）
1. 为患者建档、补全关键字段（例如分期、基因突变、既往治疗）
2. 重跑匹配并对结果进行解释与沟通（为什么匹配/不匹配）
3. 记录匹配历史，方便复盘

## 4. 产品目标与衡量指标（建议）

### 核心北极星指标
- **有效候选试验数**：每位患者产生的「可入组且可联系」候选试验数量（去重、去无效）。

### 辅助指标
- **链路完成率**：注册→建档→上传→解析→匹配→查看结果的漏斗
- **首屏时间 & 匹配等待时间**：上传后到结构化结果出现、到首批匹配返回的耗时
- **质量指标**：人工评审下的匹配准确率/召回率（可后续加标注集）
- **成本指标**：OCR/LLM 调用次数、token 成本、失败重试率

## 5. 功能边界（当前 & 规划）

### 已具备（仓库现状）
- 用户注册/登录（JWT）
- 患者列表/详情/更新/删除
- 上传文件并 OCR（支持本地 fallback/mock）
- 医疗文本解析（支持 LLM/非 LLM）
- 匹配：传统/增强匹配；批处理 + SSE 流式输出进度与结果
- 匹配历史：保存/恢复
- 试验缓存：加载试验数据、统计地点

### 明确不做（本 Demo 默认不包含）
- 真实医院 HIS/EMR 对接
- 多租户权限体系（机构/科室/医生级别）
- 线下研究中心对接流程自动化（短信/IM/CRM）
- 完整的患者知情同意流程与合规模板（可在 `docs/legal/` 扩展）

## 6. 术语表（面向沟通统一）

- **PHI/PII**：可识别个人信息/健康信息（姓名、电话、身份证号、住院号等）。
- **OCR**：从 PDF/图片中提取文本。
- **结构化病历**：从自由文本抽取出的字段集合（诊断、分期、基因、治疗史等）。
- **匹配（Matching）**：根据结构化病历与试验入排标准计算匹配度并给出解释。
- **SSE**：Server-Sent Events，用于流式推送匹配进度与分批结果。

## 7. 产品结构（信息架构）

- 首页：产品价值说明、入口
- 认证：登录/注册、合规协议页
- 患者：
  - 列表：创建/检索/进入患者
  - 患者工作流：上传 → 抽取 → 结构化 → 结果
- 历史：查看历史匹配记录/恢复
-（可选）试验：缓存状态、地点统计（API 支持）

## 8. 关键产品决策（推荐默认值）

- 前端统一走 `Next.js /api` 代理：减少跨域与环境切换成本。
- 匹配采用「先快后准」：
  - 首屏快速规则/筛选（召回）
  - 再用更重的 LLM/增强算法精排（精度）
- 任何涉及 PHI 外发的能力必须具备开关与默认保护（见 `04-隐私与安全.md`）。
