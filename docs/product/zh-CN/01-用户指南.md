# 用户指南（面向使用者）

本指南按「最短上手」组织：你可以把它当作产品说明书（Demo 可演示、可实际跑通）。

## 1. 我能用它做什么？

- 为患者建立档案
- 上传/粘贴病历文本并自动抽取关键字段
- 一键匹配可入组的临床试验，查看匹配理由、筛选与保存
- 回看/恢复历史匹配结果，便于复盘与沟通

## 2. 使用前准备（建议）

- 你需要准备：一份病历文本或 PDF/图片（化验单、病理、出院小结等）
- 建议准备的关键字段（越完整越准）：
  - 诊断（肿瘤类型）
  - 分期/分级（如 TNM、BCLC 等）
  - 关键基因突变/融合（如 EGFR、ALK、HER2 等）
  - 既往治疗史（手术/放化疗/靶向/免疫）

## 3. 快速使用（UI 操作）

### 3.1 注册/登录

1. 打开前端页面（默认 `http://localhost:3000`）
2. 进入「注册」填写邮箱、姓名、密码并勾选合规协议
3. 注册后会自动登录；也可在「登录」页登录

提示：
- 密码策略：至少 8 位，含大小写字母与数字
- 登录后系统会自动拉取当前用户信息（用于保持会话）

### 3.2 创建患者档案

路径：`患者列表` → `创建患者`

推荐填写：
- 患者编号（便于运营侧识别；系统会在冲突时自动调整）
- 姓名、性别、出生日期（可选）
- 联系方式（邮箱/电话/地址，可选）
- 备注/标签（如「已做基因检测」「一线失败」）

### 3.3 上传病历并解析

路径：`患者详情` → `上传` → `抽取` → `结构化`

你可以：
- 上传 PDF/图片/文本文件（系统会进行 OCR/抽取）
- 或直接粘贴文本（走 `/api/medical/parse`）

常见问题：
- 如果 OCR 服务不可用，系统可在允许的配置下启用 mock/fallback（运维可控）
- 解析输出的字段可用于后续匹配与解释（建议人工快速校对关键字段）

### 3.4 启动匹配并查看结果

路径：`患者详情` → `结果`

特点：
- 支持「批处理 + 流式」：先返回首批结果，再逐步补齐
- 支持筛选：按地区/状态/分期/突变等（取决于试验数据完整度）
- 支持保存：将候选试验加入「已保存」便于后续跟进

## 4. 输出怎么解读（建议话术）

- **匹配分数**：用于排序参考，不等同于可入组结论
- **匹配理由**：系统根据入排标准与患者关键字段给出解释
- **待确认项**：缺失字段会降低准确率，建议补充检查/影像/病理等信息

> 推荐流程：先把候选试验列表“缩到 3-10 个”，再由人工核对入排标准并联系研究中心。

## 5. 常见问题（FAQ）

### 5.1 登录后又被退出？
可能原因：
- Token 过期/无效
- 后端未实现 `/api/auth/me`（本仓库已补齐）

### 5.2 上传后没有解析结果？
可能原因：
- OCR 服务不可用或超时
- 文件为空/图片过糊
- 后端无法写入 uploads 目录（容器挂载/权限问题）

### 5.3 匹配一直在转圈？
可能原因：
- 试验数据为空或未加载（检查是否已执行 `server/setup` 或 Docker 初始化）
- SSE 连接被代理/网络中断（检查浏览器 Network EventStream）
