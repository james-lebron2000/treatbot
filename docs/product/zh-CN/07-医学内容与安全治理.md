# 医学内容与安全治理（CMO 视角）

> 目标：让系统输出在医学上“可解释、可复核、可追责”，并把误用风险降到最低。

## 1. 产品定位与免责声明（必须前置）

- 本系统输出为“临床试验候选筛选与解释”，**不构成诊断、治疗建议或入组结论**。
- 所有候选结果必须由临床医生/研究协调员结合原始材料与试验方案最终确认。
- 对关键缺失信息必须做“待确认项”提示（例如：分期、ECOG、肝功能、既往线数等）。

## 2. 最小医学数据集（MVP 必须覆盖）

为提高匹配质量，建议结构化字段至少包含：

**肿瘤基本信息**
- 原发部位/病理类型（例如 HCC、iCCA、NSCLC 等）
- 分期/分级（TNM/BCLC/Child-Pugh 等）
- 疾病状态（复发/转移、是否可切除）

**治疗史**
- 既往治疗线数（0/1/2/…）
- 关键疗法：手术/放疗/化疗/靶向/免疫/介入
- 最近一次治疗时间点（影响 washout）

**分子与检验**
- 关键驱动基因/融合/扩增（EGFR/ALK/HER2…）
- 重要肿瘤标志物（AFP/CEA/CA19-9 等）
- 基础实验室（肝肾功能、血象）——至少能提示“缺失”

**一般条件**
- 年龄、性别
- ECOG/体能评分
- 合并症与禁忌（例如活动性感染、自免病、出血风险等）

> 备注：MVP 阶段可以先做“抽取 + 缺失提示 + 人工补全”，不要试图一次性全自动。

## 3. 试验数据治理（来源、更新与可追溯）

必须明确每条试验数据的：
- 来源（CSV/人工整理/公开注册库）
- 更新时间与版本号（便于解释“为什么昨天能匹配今天不能”）
- 招募状态与地区字段的质量（缺失会影响筛选）

建议机制：
- 试验数据导入时生成 `trialDataVersion`
- 每次匹配结果写入 `ruleVersion` + `trialDataVersion`（可复盘）

## 4. 匹配逻辑治理（规则/模型/提示词）

**推荐“先快后准”的两段式：**
1) 规则召回：地区/年龄/性别/状态/关键突变等硬条件先筛掉不可能的
2) 精排解释：对入排标准给出逐条命中/不确定的解释

**对 LLM 的建议：**
- 默认 `LLM_PHI_MODE=disallow`
- 只有在明确合规与告知后才允许把医疗文本外发给第三方模型
- 即使启用 LLM，也应优先传“结构化字段 + 脱敏摘要”，不要传原文全文

## 5. 医学安全机制（必须实现的“护栏”）

- **高风险字段缺失拦截**：例如分期/驱动基因缺失 → 输出必须提示“结果可信度降低”
- **不确定性表达**：输出需要区分“满足/不满足/未知”，避免二元断言
- **解释一致性**：每条推荐必须能给出理由（命中的标准/冲突点）
- **人工复核入口**：运营侧可以补全字段后重跑匹配

## 6. 质量评估（把 Demo 变成可运营系统）

建议建立最小评估闭环：
- 抽样 50–200 例匿名病例，人工标注“应该匹配/不应匹配”的试验集合
- 指标：Top-K 命中率、召回、解释可用性（可复核率）
- 每次规则或数据更新都跑回归集
