# 部署与运维

本项目提供两种推荐运行方式：Docker 一键启动（最稳）与本地开发启动（最灵活）。

## 1. Docker 一键启动（推荐）

### 1.1 准备环境
- 安装 Docker Desktop（macOS/Windows）或 Docker Engine（Linux）
- 准备环境变量：复制 `.env.example` 为 `.env` 并按需填写

### 1.2 启动

```bash
cp .env.example .env
./deploy/one_click_docker_compose.sh
```

### 1.3 健康检查

- 前端：`http://localhost:${FRONTEND_PORT:-3000}`
- 后端健康：`http://localhost:${FRONTEND_PORT:-3000}/api/health`

> 注意：前端通过 Next.js `/api/*` 代理访问后端，因此通常只需访问前端端口。

## 2. 本地开发启动（不使用 Docker）

### 2.1 依赖
- Node.js 16+（建议 18/20）
- MongoDB（本地或云端）
- （可选）Redis：仅在启用队列/缓存时需要
- （可选）Python 3：用于 OCR 微服务

### 2.2 安装

```bash
npm run install-all
```

### 2.3 配置

确保以下至少存在：
- `server/.env` 或根目录 `.env`：包含 `MONGODB_URI`、`JWT_SECRET`
- `client/.env.local`：默认已配置 `NEXT_PUBLIC_API_BASE_URL=/api`

### 2.4 初始化试验数据

```bash
cd server
npm run setup
```

### 2.5 启动

```bash
# 前后端一起（推荐）
npm run dev

# 或分别启动
cd server && npm run dev
cd client && npm run dev
```

## 3. 关键环境变量（速查）

### 必填（后端启动必需）
- `MONGODB_URI`：MongoDB 连接串
- `JWT_SECRET`：JWT 签名密钥

### 常用（按需）
- `PYTHON_OCR_URL`：OCR 服务地址（默认 `http://localhost:5002`）
- `ALLOW_OCR_MOCK`：是否允许 mock OCR（默认建议 `false`）
- `ALLOW_OCR_TESSERACT_FALLBACK`：Python OCR 失败时是否允许 tesseract 回退（默认建议 `false`）
- `OPENAI_API_KEY`、`baseURL`：OpenAI 兼容模型（例如 Moonshot/Kimi）
- `LLM_PHI_MODE`：涉及医疗文本外发的隐私模式（见 `04-隐私与安全.md`）
- `STRICT_MODE`：严格模式（`true` 时禁用隐式回退、强制 OCR+LLM 必须可用）
- `REQUIRE_LLM`：即使非严格模式也强制要求 LLM 配置
- `ALLOW_PARSING_FALLBACK`：LLM 解析失败时是否允许回退到规则解析（严格模式下固定为 `false`）
- `TRIAL_CSV_PATH`：试验 CSV 路径
- `ALLOW_TRIAL_REFRESH`：是否开启 `/api/trials/refresh`

## 4. 观测与排障

### 4.1 快速定位
- 后端健康：`GET /api/health`
- OCR 健康：`GET /api/medical/ocr/health`（需登录且为管理员角色）
- 指标：`GET /api/metrics`（生产环境需 `METRICS_TOKEN`）

> 说明：生产环境下 `/api/health` 默认只返回最小信息；如需详细依赖/配置健康信息，请设置 `HEALTH_TOKEN` 并使用请求头 `Authorization: Bearer <HEALTH_TOKEN>`。

### 4.2 常见故障

- **Mongo 连接失败**：确认 Mongo 是否启动、`MONGODB_URI` 是否可达
- **前端能开但 API 404/500**：确认前端是否走 `/api` 代理（`NEXT_PUBLIC_API_BASE_URL=/api`）
- **CORS 报错**：通常意味着绕过了 `/api` 代理直接访问后端；建议统一走代理或配置 `CORS_ALLOWED_ORIGINS`

## 5. 生产建议（最小化清单）

- 使用 Docker Compose 部署，前后端分容器
- 为 Mongo/Redis 配置持久化卷
- 关闭不必要的调试日志，启用访问日志与 traceId
- 明确 PHI 外发策略：默认禁用或强脱敏（见 `04-隐私与安全.md`）

## 6. Mac mini 单机部署（内测/小规模试运行推荐）

当你用一台 Mac mini 承载服务时，建议把“数据库数据 + 上传文件”放在一个独立的数据目录（最好是外接 SSD），并确保可备份/可迁移。

### 6.1 准备数据目录

- 规划：至少预留 200GB（按 10000 份 × 20MB 文件估算，不含备份冗余）
- 路径建议：`$HOME/ClinicalMatchData`（Docker Desktop 默认共享），或外接盘路径（需在 Docker Desktop File Sharing 中授权）

### 6.2 启动（带持久化 bind mounts）

```bash
cp ./deploy/macmini.env.example .env
# 编辑 .env：设置 HOST_DATA_DIR 与 JWT_SECRET
./deploy/macmini_one_click.sh
```

### 6.3 备份（最小可用）

```bash
./deploy/macmini_backup.sh
```

> 提示：上传文件建议用 `rsync` 做增量备份到另一块盘或云端对象存储；数据库 dump 与文件备份分开做更可靠。

### 6.4 留存清理（3 年留存）

本项目支持对文件元数据执行“到期删除”的运维脚本（默认 dry-run，避免误删）。

```bash
cd server
npm run retention:dry
```

确认输出无误后再执行真实删除（单次默认最多处理 500 条，可用 `RETENTION_MAX_DELETE` 控制）：

```bash
cd server
RETENTION_MAX_DELETE=500 npm run retention:run
```
